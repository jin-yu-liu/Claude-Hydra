### 安全性重点：虚拟沙盒与指纹防护

本版本新增虚拟沙盒与多层指纹防护，让每个账号在网络、设备和浏览器层面都彼此隔离，显著提高多账号使用的安全性。

- 虚拟沙盒隔离（可在环境中按需开启）
  - Windows：账号的 Claude 运行在 Sandboxie-Plus 沙盒中，只能连接本账号的本地中继；启动后会核实确实在沙盒内，否则自动关闭
  - macOS：账号的 Claude 运行在系统 Seatbelt 沙盒中，只放行本账号的中继端口，本机代理和其他账号的中继都无法访问；启动前自检，规则不成立就拒绝启动
  - DNS 防泄漏：沙盒内不能走系统 DNS，也不能直连外部地址
- 设备指纹隔离（Windows 沙盒）
  - 每个账号看到自己的设备标识：MachineGuid、硬件配置 GUID、主机名、卷序列号、网卡 MAC
  - 账号名与 SID、主板 / BIOS / 内存 / 磁盘序列号和系统 UUID 按账号派生；WMI 在沙盒内关闭，避免绕过
  - 开启沙盒时强制使用独立的 Claude Code 目录，各账号不再共用同一个 Claude Code 设备 ID
- 网页指纹防护（Windows 账号浏览器与 macOS）
  - Canvas、WebGL 显卡信息、字体测量、屏幕分辨率、CPU 核数与内存按账号派生：同一账号始终一致，不同账号互不相同
- 出口保护与账号专属浏览器
  - 环境可绑定出口国家 / IP，启动前和运行中持续核对，出口不符时切断该账号网络
  - 登录和外部链接在与账号同出口 IP、同时区的独立浏览器中打开
  - Claude 及其子进程只经本地中继出网，没有直连回退
- 密码保护（macOS）：节点密码和订阅信息改用登录钥匙串中的密钥加密保存，旧配置会自动迁移

### 改进

- 出口核验只在确认违规时断网，核验失败会自动重试并恢复；账号页显示“核验中断网”状态
- 切换节点或重新绑定环境时，会重新核验正在运行的账号
- 保留 Clash 订阅节点并隔离每个账号的出口代理策略；移除 Clash 文件导入入口，只显示实际订阅节点
- 新增 Sandboxie 静默启动设置
